## Goal

Add per-profile, cycle-aware period reminders that schedule deterministically
and reconcile idempotently — without coupling domain logic to Expo.

## Scope

### In

- `NotificationPreference` entity (per-profile enabled/daysBefore)
- Realm schema v1→v2 migration (additive: new object type)
- Three-layer notification architecture (domain → reconciliation → infra)
- Deterministic notification IDs for idempotent scheduling
- Set-diff reconciliation (not cancel-all/reschedule-all)
- Settings UI: toggle + days-before picker
- Fire-and-forget sync at 6 trigger points
- DEV-only structured logging (`[NotifSync]`)

### Out

- Multi-cycle forecasting (MVP: `maxReminders=1`)
- Customizable fire time (hardcoded 09:00 local)
- Delete-profile UI (no UI exists; repo method is tested)
- iOS support

## Constraints

- Domain layer (`notificationPlan.ts`) must be pure TS — no Expo imports, time-injected
- Reconciliation layer must depend only on `NotificationAdapter` interface
- Realm migration must be additive (no data transformation)
- All new logic must be testable via `MemoryRepo` + `MemoryNotificationAdapter`

## Architecture Decisions

- **ADR 0006** ([docs/adr/0006-notification-preferences.md](../adr/0006-notification-preferences.md)): Realm storage, adapter pattern, deterministic IDs, 3-layer arch
- ID format changed from `fc-remind-{profileId}-{targetDateIso}` to `fc-remind-{profileId}-{fireDateIso}T{HH:mm}` — ensures daysBefore changes produce new IDs and trigger correct cancel+reschedule
